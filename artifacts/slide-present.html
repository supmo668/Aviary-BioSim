Problem

Self-improving agents grade their own homework.

An agent writes the code, runs the check, and reports success. When the check is weak — or silently broken — nothing notices, and the loop gets confidently better at passing a test nobody enforces.

It happened to us
Our test runner was never given the library it needed in order to run tests. It exited with code 1 — and our own rule read code 1 as "a test failed".
The consequence
Every task would have exhausted its retries and been set aside while the test never ran once. Our 36-test suite passed throughout.
The hypothesis
A loop is only trustworthy if whoever does the work cannot be the one who decides it passed.
Solution & methods

Separate the worker from the gate. Then point it at biology.

Adoption — what we reused
Aviary (Future-House) for the environment contract, ESM-2 650M on Apple MPS, UniProt for sequences, W&B Weave for tracing, W&B Inference so no GPU sits on the critical path.
Reasoning — what we built
A checker with no language model in it, which reads the test runner's own report rather than trusting its exit code, and BioSimEnv — an aviary Environment whose step() runs a protein model instead of a simulation.

Conclusion

The loop produced the instrument that produced the result.

It built its own tools
The loop's first pass produced a budget guard, every behaviour proven by an independent test. That same component is now a tool in the aviary environment, metering the agent that uses it — and has been contributed upstream.
It knows when to stop
A pass that completes no new work ends the loop. Not a timeout, not a fixed count — an actual convergence signal.
It reached a known answer
Six cysteines, correct chain assignments, a self-chosen control, and a second tier of hydrophobic core residues — none of it in the prompt.

Discussion

What this does not show.

  • ESM-2 has seen insulin. This is recovery of known constraint, not discovery of new biology. The claim is that an agent can plan and execute a measurement campaign and arrive at an independently-known answer — nothing more.
  • A trace shows stated reasons, not causes. We can read what the agent said it was doing. Whether that is why it did it is a different question, and not one a trace answers.
  • No wet experiment has been run. The pre-registered design is assessable from the literature; its conclusions are not, because there are none yet.
  • Two of our sequence labels were wrong — a rattlesnake fragment labelled chicken, Xenopus labelled zebrafish. The data caught it. Labels now come from the database, never from us.
  • And the one that matters most. Three defects surfaced today and they are one shape: a mechanism reported success while the property it existed to guarantee was absent. All three were caught by hand. The check catches work that fails. It is blind to a mechanism that passes for the wrong reason.
  • And the shape is not only ours. Applying the same lens to a mature, pre-existing quality gate elsewhere in our tooling found a suite of entirely skipped tests signing green — it had a self-test, and the self-test passed. The pattern is not a story about a codebase written in a day.
What we would do next
Record the exact instructions each task was given. That is where the difficulty actually lives, and until it is recorded a run is attributable but not reproducible. We narrowed the claim rather than overstate it.
